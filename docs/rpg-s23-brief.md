## 슬라이스 1이 임시로 둔 것 — 이번 입력이다

- 높이가 `min(470px, 100svh - 250px)` 고정 계산이다. **실측 사각형 기반 반응형이 아니다.**
- 물이 사각형이고 나무가 드물다. 지형이 미완성이다.
- 상호작용이 없다. 다가가도 아무 일도 일어나지 않는다.
- NPC 통행 데이터가 없다.

## 이번에 만드는 것 — 슬라이스 2와 3

### 슬라이스 2 — 반응형 높이·입력 완성·캐릭터 생성 기반

설계서 §2의 공식을 실제로 구현한다: `H = min(520, 하단 탭 윗변 − iframe 윗변 − 16)`

**520을 일괄로 박지 마라.** 설계서 §2 실측이 320×568에서 iframe이 하단 탭 뒤로
들어감을 보였다. 부모가 실제 사각형·visual viewport·safe-area 변화 후 계산해야 한다.

H가 300px 미만일 때의 처리(제목 부제 접기 → 그래도 부족하면 "세로로 돌려서 계속하기")도
설계서 §2에 있다. 그 상태에서 입력이 계속되거나 게임이 탭 뒤에서 동작하면 안 된다.

입력 완성: 멀티터치(패드 + 행동 버튼 동시), blur, 회전, 부모 스크롤 충돌.

### 슬라이스 3 — 지형·채집점·타깃 판정·꾸미기 3종

- 설계서 §2의 「지도의 장소」대로 집 앞 마당 · 나무 그늘 · 연못 · 오솔길을 완성한다.
- 설계서 §4의 근접 판정: **발 위치 40월드px 이내, 바라보는 방향 ±60도, 차단물 없음.**
- 꾸미기 3종(화분·우물·의자), 최대 48개, 1타일. 배치 모드에서도 패드로 걸을 수 있다.
- NPC가 쓸 통행 데이터를 함께 만든다(주민 자체는 6일차다).

## 반드시 지킬 것

### 판 탭 게임으로 되돌아가지 않는다
설계서 §11의 3일 게이트가 이것을 명시한다 — **"먼 물건 버튼 획득 0, 가까이서만 반응."**
화면의 물건을 탭해서 즉시 얻는 입력을 만들면 이번 재설계가 무의미해진다.
배치 미리보기도 **캐릭터 앞 한 타일**을 따른다. 화면 아무 데나 찍는 배치가 아니다.

### 도달 가능성을 검증한다
48개를 다 놓아도 집 입구에서 각 채집 장소·낚시점에 갈 수 있어야 한다.
길을 완전히 막는 배치는 **이유를 보여주며 거절**한다.

### 자산은 코드 생성 또는 동봉 script
외부 PNG·JSON을 fetch하면 CORS로 막힌다(sandbox 실측). 지도도 일반 JS로 동봉한다.

### 규칙과 표현을 가른다
`rpg-rules.js`에 Phaser·DOM을 넣지 마라. 엔진 접촉은 `rpg-engine.js`에만.

### 저장은 아직 fixture다
실제 저장은 4·5일차다. 이번에 5키 codec을 미리 만들지 마라.

## 완료 게이트 — 설계서 §11의 2·3일 행

슬라이스 2:
- 부모 320×568 / 360×780 / 430×900에서 **H의 초기 예상(318/520/520)과 실제 차이를 기록**

- 버튼 ≥ 44×44 CSS px
- 패드/행동 멀티터치 · blur · 회전 · 부모 스크롤 검증
- `game-backyard-input.test.ts` 및 DOM 타입 검사 통과

슬라이스 3:
- `game-backyard.test.ts`에서 **막힌 길 · 점유 · 지도 경계 · 40px 범위 · 벽 너머 상호작용 거절**
- **48개 배치 최대에서도 모든 필수 장소 도달 가능**
- **먼 물건 버튼 획득 0, 가까이서만 반응**

기존 게이트도 깨지지 않아야 한다:
```
pnpm exec turbo run build --filter="./packages/*" --force --concurrency=2
pnpm --filter @family/web typecheck
pnpm --filter @family/web exec tsc -p tsconfig.miniapps-rules.json --noEmit
pnpm --filter @family/web exec tsc -p tsconfig.miniapps-dom.json --noEmit
pnpm --filter @family/web build:mobile
```

## 지켜야 할 것

- **슬라이스 4 이후를 미리 만들지 않는다.** codec·session·주민·채집·낚시·도감은 이번이 아니다.

- 확인 못 한 것은 **"확인 못 함"**이라고 쓴다. 사람이 해야 하는 관찰을 자동 결과로 대신하지 마라.
- `build:packages`가 `FULL TURBO`면 검증이 아니다. `--force`로 확인한다.
- 출력은 파일로 받는다 — `| tail`은 vitest를 EPIPE로 죽여 없던 실패를 만든다.
- **운영 스택(`docker-compose.prod.yml`)에 쓰지 않는다.**
