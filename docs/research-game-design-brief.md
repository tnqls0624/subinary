# 설계 지시서 — 동물의 숲 참고 타이쿤 게임 (2026-09-05)

> 라이브러리 조사(`docs/research-game-library-2026-09.md`)는 끝났다(Phaser 추천).
> 이 작업은 **무슨 게임을 만들 것인가**를 정하는 것이다. 코드는 쓰지 않는다.

## 만들 것

**동물의 숲을 참고한 타이쿤/생활 시뮬레이션.** 다만 동물의 숲을 그대로 옮기는 것이
아니라, 아래 제약 안에서 **실제로 재미있는 가장 작은 게임**을 설계한다.

## 제약

| 항목 | 내용 |
|---|---|
| 실행 | `<iframe sandbox="allow-scripts">` 안의 정적 미니앱. 서버 로직 없음 |
| 저장 | 부모에 `postMessage`로 JSON 하나. 8KB 이내 |
| 세션 | 모바일에서 **짧게 자주** 여는 패턴. 한 번에 30초~3분 |
| 제작 | 1인이 만든다. 아트 자산을 대량으로 만들 수 없다 |
| 인원 | 사용자 2명(가족). 랭킹·경쟁·소셜 기능은 의미 없다 |

## 설계할 것

### 1. 핵심 루프

플레이어가 반복하는 30초~3분짜리 행동. "무엇을 하고, 무엇을 얻고, 그것으로 무엇을
하는가". 동물의 숲의 루프를 그대로 쓰지 말고 **이 제약에 맞게 줄인 것**을 설계한다.

### 2. 시간 설계

동물의 숲은 실시간에 묶여 있다. 우리도 그럴 것인가?

- 실시간(현실 시각)으로 하면: 다시 열 이유가 생기지만 오래 안 열면 죄책감이 된다
- 게임 내 시간만 쓰면: 언제 열어도 같지만 "기다림"의 재미가 없다

**어느 쪽이든 근거를 적는다.** 이 결정이 저장 모델과 알림 필요 여부를 정한다.

### 3. 성장과 목표

무엇이 쌓이고, 무엇이 해금되고, 어디까지 가면 "다 했다"인가. 끝이 없는 설계라면
그 이유를 적는다.

### 4. 저장 모델

8KB JSON에 무엇을 담는가. 필드 목록과 대략의 크기를 계산한다. **엔진 객체를 통째로
직렬화하지 않는다** — 좌표·ID·시각만 담고 나머지는 로드 시 재생성한다.

### 5. 아트 범위

1인이 만들 수 있는 최소 자산. 도트인가 도형인가, 몇 종류가 필요한가. 자산을 코드로
생성(캔버스 도형)할 수 있으면 그것도 검토한다 — sandbox에서 이미지 로딩이 막힐 수
있다는 선행 조사 지적과 이어진다.

### 6. 첫 번째 버전(v0)

**일주일 안에 만들 수 있는 가장 작은 플레이 가능한 것.** 무엇을 넣고 무엇을 뺄지
명확히 가른다. "나중에 추가할 것" 목록도 함께.

## 참고할 것

- 동물의 숲의 어떤 요소가 재미의 핵심인지 분석한다(수집·꾸미기·시간·캐릭터 중 무엇인가)
- 웹 기반 소규모 타이쿤/생활 시뮬 게임의 실제 사례가 있으면 참고한다
