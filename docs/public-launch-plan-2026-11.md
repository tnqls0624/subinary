# 공개 서비스 오픈 계획 (2026-11)

> **상태: 초안 v4 (2026-11-22).** v1(2026-11-11)은 문자 자동 수집을 선택 기능으로 두었다. PO 결정에 따라 **앱의 가이드로 iPhone 문자까지 자동 수집하는 것**을 공개판의 핵심으로 다시 짰다 (v2). v3은 문장 점검 결과, 하단 탭 수정, 실행 작업 목록(6-1)을 반영했다. v4는 PO 결정(2026-11-22)에 따라 단축어가 문자를 앱의 App Intent에 넘기는 방식(ADR-0038)을 기각하고, iPhone 수집을 지금처럼 단축어가 서버로 직접 보내는 방식(ADR-0016)으로 되돌렸다.
> `결정 필요`로 표시한 항목은 아직 정하지 않았다. 운영 데이터나 사용자 조사로 확인하지 못한 추정은 `[가설]`, 실기기나 공식 문서로 확인해야 하는 사실은 `[확인 필요]`로 표시한다.
> 외부 규정·정책은 10장에 확인 날짜와 출처를 적는다. 출시 직전에 다시 확인한다.
> 기준 문서: [`PRD.md`](../PRD.md), [`product-roadmap.md`](./product-roadmap.md) C-2, [`family-finance-renewal-2026-11.md`](./family-finance-renewal-2026-11.md), [`adr/0007`](./adr/0007-device-hmac-authentication.md), [`adr/0016`](./adr/0016-device-token-ingest.md), [`adr/0037`](./adr/0037-four-tab-navigation.md), [`adr/0038`](./adr/0038-ios-app-intent-sms-ingest.md) (기각한 iPhone App Intent 방식).

## 1. 목표와 성공 기준

**목표**: iPhone과 Android 사용자 모두, 앱의 가이드만 따라 하면 카드 결제 문자가 자동으로 가족 가계부에 들어온다.

**iPhone 원칙**: 앱은 문자함을 읽지 않는다. 사용자가 단축어 앱에서 만든 자동화가 카드 문자를 서버의 토큰 경로(ADR-0016)로 직접 보낸다. iOS에서는 앱이 문자함을 직접 읽을 수 없고, 메시지 필터 확장도 수집에는 쓸 수 없다 (10장). 그래서 문자가 오자마자 받으려면 사용자가 만든 단축어 자동화를 거쳐야 한다.

**성공 기준**: 공개판의 성패는 **설정 완주율**이 가른다. 설정을 끝내지 못하면 카드 거래가 자동으로 들어오지 않아 홈과 가계부가 거의 빈 채로 남기 때문이다 (로드맵 C-2와 같은 판단).

| 지표 | 정의 | 목표 |
|---|---|---|
| 설정 완주율 | 등록한 기기 중 첫 카드 문자가 서버에 도착한 기기 비율 (`firstEventAt`) | `결정 필요` |
| 설정 소요 시간 | 기기 등록부터 첫 문자 도착까지 | `결정 필요` |
| 수집 유지율 | 첫 문자 뒤 7일, 30일이 지나도 문자가 계속 들어오는 기기 비율 (`lastEventAt`) | `결정 필요` |

## 2. 이미 있는 것

| 자산 | 위치 | 공개판에서의 쓰임 |
|---|---|---|
| 문자 수집 API: HMAC 서명 경로, 수집 토큰 경로 | ADR-0007, ADR-0016 | iPhone 단축어와 MacroDroid 모두 토큰 경로를 그대로 쓴다 (3장) |
| 수집 설정 마법사 (앱 설치 → 설정 옮겨 적기 + 연결 확인 → 첫 문자 대기) | `apps/web/src/components/collect-setup-wizard.tsx` | 그대로 쓰고 iPhone 안내를 보강한다 (3-4) |
| Signal Doctor (마지막 인증·첫 문자·마지막 문자 시각을 보고 수집이 끊긴 원인을 좁힘) | `apps/web/src/lib/device-signal.ts` | iPhone에서만 생기는 원인을 추가한다 |
| 수집 공백 경보 | `apps/worker/src/notifications/notification-scheduler.service.ts` | 그대로 쓴다 |
| 카드사별 파서, 문자 단위 중복 방지(`eventId`) | `packages/card-parsers`, ADR-0016 | 그대로 쓴다 |
| 문자 원문 보존 기간과 삭제 기록 | `sms_raw_retention`, `sms_raw_purge` | 공개판에도 적용한다 |

**iPhone 단축어 방식의 한계** (App Intent 방식을 기각했으므로 공개판에서도 안고 간다)

1. 사용자가 단축어의 'URL 콘텐츠 가져오기' 동작에 주소, 헤더, 본문을 칸마다 옮겨 적어야 한다. 단계가 많고 틀리기 쉽다.
2. 수집 토큰이 단축어 안에 평문으로 남는다. 단축어를 공유하거나 화면을 캡처하면 그대로 샌다. 토큰을 회전하면 사용자가 단축어를 다시 고쳐야 한다.
3. 전송에 실패하면 그 문자는 가계부에 들어오지 않고 끝난다. 단축어는 스스로 재시도하지 않는다.

## 3. iPhone 수집: 단축어가 서버로 직접 보낸다

### 3-1. 구조

```
카드 문자 수신
 → 사용자가 만든 단축어 자동화 (메시지 수신 시, 즉시 실행)
 → 'URL 콘텐츠 가져오기' 동작
 → POST /v1/mobile-events/card-sms-token (Bearer 수집 토큰, ADR-0016)
```

지금 가족 기기에서 쓰는 방식 그대로다. 수집 설정 마법사가 주소, 헤더, 본문 값을 칸마다 복사할 수 있게 보여 준다.

### 3-2. 기각한 방식: App Intent (ADR-0038)

단축어가 문자를 앱의 App Intent에 넘기고, 앱이 기기 안에서 카드 문자만 골라 HMAC 경로로 보내는 방식을 검토하고 시제품까지 만들었다. 2026-11-22 PO가 '단축어를 통한 등록이 이제 안 된다'며 기각했고 `[확인 필요: '등록'이 가리키는 범위]`, 시제품 코드는 지웠다. 그래서 2장의 한계(값 옮겨 적기, 단축어 안의 평문 토큰, 재시도 없음)는 공개판에도 남는다.

### 3-3. 자동화 조건 `결정 필요`

기기 안에서 카드 문자를 걸러 내는 단계가 없으므로, 자동화 조건이 곧 어떤 문자가 서버로 가는지를 정한다. 승인 문자와 취소 문자를 모두 잡아야 한다.

| 안 | 방법 | 장점 | 단점 |
|---|---|---|---|
| A. 조건 없음 | 모든 메시지에 자동화를 실행해 서버로 보낸다 | 사용자가 넣을 조건이 없다 | 인증번호, 광고처럼 카드 문자가 아닌 문자도 서버로 간다. 개인정보 처리방침에 그대로 적어야 한다 |
| B. 키워드 조건 | '승인', '취소' 등 키워드가 든 메시지에만 실행 | 카드 문자가 아닌 문자가 덜 간다 | 키워드마다 자동화를 따로 만들어야 할 수 있다 `[확인 필요: 조건에 키워드를 여러 개 넣을 수 있는지]`. 문구가 다른 카드사를 놓친다 |
| C. 발신자 조건 | 카드사 번호에서 온 메시지에만 실행 | 카드사가 아닌 번호에서 온 문자는 서버로 가지 않는다 `[확인 필요: 카드사가 같은 번호로 광고도 보내는지]` | 카드사 번호를 연락처에 저장해야 고를 수 있을 것으로 보인다 `[확인 필요]`. 카드사마다 번호가 여럿이다 |

### 3-4. 가이드 보강

| 가이드 단계 | 사용자가 하는 일 | 앱이 하는 일 |
|---|---|---|
| 1. 기기 등록 | 앱 설치, 로그인, '이 iPhone 연결하기' | 연결 열쇠(수집 토큰)를 이 창에서 한 번만 보여 준다 |
| 2. 카드 알림 확인 | 카드 결제 알림이 **문자**로 오는지 확인 | 카드사 앱 푸시나 카카오 알림톡으로만 받는 사용자에게 카드사별 문자 알림 신청 방법을 안내 (유료일 수 있음) `[가설: 이런 사용자의 비율 미확인]` |
| 3. 자동화 만들기 | 단축어 앱 → 자동화 → 새 자동화 → 메시지. 3-3에서 정한 조건, **즉시 실행** 선택 | 버튼으로 단축어 앱을 엶. iOS 버전별 화면 이미지와 20초 안팎의 영상 |
| 4. 동작 채우기 | 'URL 콘텐츠 가져오기'에 주소, 헤더, 본문을 칸마다 붙여 넣음 | 칸마다 복사 버튼 (지금 마법사) |
| 5. 확인 | 카드로 한 번 결제 (또는 다음 결제를 기다림) | 기존 마법사의 첫 문자 대기와 Signal Doctor를 그대로 씀 |

**Signal Doctor에 추가할 원인 (iPhone 단축어 기준)**

- 자동화가 '실행 전에 묻기'로 바뀌어 있음
- 자동화가 삭제됨
- 수집 토큰을 다시 발급했는데 단축어에는 옛 토큰이 남아 있음
- 카드 알림이 문자가 아닌 앱 푸시나 알림톡으로 옴

**가이드 콘텐츠 관리**

iOS가 업데이트되면 단축어 앱 화면이 바뀐다. 지원하는 iOS 버전마다 화면 이미지를 관리하고, 새 iOS가 나오면 가이드를 다시 점검한다 (로드맵 C-2의 위험과 같다).

### 3-5. 실기기 시험

| 시험 | 확인할 것 |
|---|---|
| 지원하는 iOS 버전마다 | '즉시 실행'으로 설정해도 확인 창이 뜨지 않는가 `[확인 필요]` |
| 화면 잠금 상태 | 정상 전송되는가 |
| 1분 안에 문자 두 통 | 둘 다 기록되는가 |
| 장문 문자, 해외 결제 문자 | 잘리지 않는가 |
| 저전력 모드 | 실행이 늦어지거나 빠지지 않는가 |
| 3-3에서 고른 조건 | 조건에서 뺀 문자(인증번호 등)가 서버로 가지 않는가 (A안이면 해당 없음) |

### 3-6. Android

- MacroDroid 가이드를 유지한다.
- 지금 가이드는 트리거를 'SMS 수신' 전체로 잡아서 인증번호 같은 문자도 서버로 간다 (`docs/api/card-sms.md` 225행). **공개판에서는 트리거에 조건(발신 번호 또는 키워드, `결정 필요`)을 넣어** 다른 문자가 서버로 가지 않게 바꾼다.
- MacroDroid에는 기기 안 판별이 없어서, 조건에서 빠진 카드사의 문자는 놓친다. 조건을 넓게 잡고(정규식), 놓친 거래는 붙여넣기로 채운다.
- 앱이 문자를 직접 읽으려면 `READ_SMS` 권한이 필요한데, Google Play는 이 권한을 제한한다. 이 방식을 쓸지는 정책을 확인한 뒤 정한다.

### 3-7. 보조 경로

- **붙여넣기**: 문자를 복사해 앱의 붙여넣기 버튼으로 기록한다 (iOS 16 이상은 붙여넣기 확인 창이 없는 버튼을 쓸 수 있다). 설정 전이거나 빠진 거래를 채울 때 쓴다.
- **파일 가져오기**: 사용자가 카드사·은행에서 직접 내려받은 파일을 검토해 가져온다 (기존 제품 계약 그대로, 4장 끝).

## 5. 공개 전에 반드시 할 일

- [ ] **앱 안에서 계정 삭제**: API, 웹, 모바일 모두. 지금은 API에 계정 삭제 경로가 없다 (2026-11-11 컨트롤러 확인). 가족 그룹 소유자가 탈퇴할 때의 처리 규칙도 정한다
- [ ] 개인정보 처리방침과 이용약관. 수집 항목, 자동화 조건에 따라 서버로 오는 문자의 범위, 보관 기간, 가족 공유 범위를 적는다
- [ ] 데이터 내보내기와 전체 삭제
- [ ] 공개판 서버에 금융·분양 사이트 로그인 정보가 **0건**인지 점검
- [ ] 금융 규제 검토: 계산과 안내까지만 한다. 상품 추천이나 대출 중개로 읽히는 문구가 없어야 한다
- [ ] 앱 심사 설명 자료: "앱은 문자함을 읽지 않습니다. 사용자가 단축어 앱에서 만든 자동화가, 사용자가 정한 조건에 맞는 문자를 서버로 보냅니다." 가이드 화면 이미지를 함께 낸다 (가이드 이미지가 있어야 해서 1단계 L-21에서 만든다)
- [ ] 운영 주체: 개인 사업자 또는 법인. 앱스토어 판매자 명의와 개인정보 보호책임자가 여기에 따라 정해진다 `결정 필요`

## 7. 지표

1장의 설정 지표가 1순위다. 그 밖에 다음을 함께 본다.

| 지표 | 정의 |
|---|---|
| 카드사별 파싱 성공률 | 받은 카드 문자 중 거래로 만들어진 비율 |
| 주간 활성 가구 | 한 주에 2명 이상 구성원이 앱을 연 가구 수 |
| 4주 유지율 | 베타 시작 4주 뒤에도 쓰는 가구 비율 |
| 보조 경로 비중 | 전체 거래 중 붙여넣기나 파일로 들어온 비율. 높으면 자동 수집이 잘 안 되고 있다는 신호 |

## 8. 위험과 대응

| 위험 | 대응 |
|---|---|
| 가이드를 따라 하다가 그만둔다 | 단계별 이미지와 영상, 단계마다 '여기서 막혔어요' 도움말, 첫 문자 대기와 Signal Doctor. 비공개 베타(6장 2단계)에서 가이드 몇 번째 단계에서 그만두는지 관찰로 잰다 |
| iOS 업데이트로 단축어 화면이나 동작이 바뀐다 | 버전별 가이드 관리, 새 iOS 베타 때 미리 점검 |
| 사용자가 자동화를 지우거나 '실행 전에 묻기'로 바꾼다 | 수집 공백 경보와 Signal Doctor로 알리고 다시 설정하게 안내 |
| 카드 알림을 문자로 받지 않는 사용자가 많다 | 카드사별 문자 알림 신청 안내. 붙여넣기와 파일 가져오기 |
| 공개 사용자의 카드사가 다양해 파서가 따라가지 못한다 | 카드사별 파싱 실패 집계. 개선용 원문 보관은 사용자 동의를 받는다 (로드맵 P1-8과 연결) |
| 개인정보 사고 | 최소 수집 (PRD §3.5). 자동화 조건(3-3)으로 카드 문자가 아닌 문자가 서버로 오는 것을 줄인다. 원문 보존 기간 적용 |
| LLM과 인프라 비용 증가 | AI 기능 포함 여부와 사용량 한도를 0단계에서 정한다 |
