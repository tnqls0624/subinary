# 신한 대출 화면 가져오기 — 로컬 구현

이 기능은 사용자가 직접 로그인한 신한 인터넷뱅킹 화면의 내용을 검토해 기록하는 기능이다.
은행 공식 API 연결, 무인 로그인, 예약 수집, 실시간 잔액 동기화가 아니다. 은행에서 받은
전자서명 자료가 아니므로 사용자가 수정한 파일의 진위를 서버가 보증할 수도 없다.

## 현재 범위

- 기존 홈·가계부·자산 3탭을 유지한다. 자산 화면에서 대출 가져오기와 본인이 가져온 기록 관리로 들어간다.
- 별도 로컬 브라우저 확장 도구가 현재 열린 `https://bank.shinhan.com`의 대출계좌 목록을 읽는다.
  사용자가 직접 실행하고 한 계좌를 선택해 JSON으로 내보낸다. 확장은 이번 작업에서 설치하지 않았다.
- V1 대상은 전세·중도금 대출의 **남은 원금, 만기일**이다. 원화 표기가 확인된 경우만 처리한다.
  과거 거래내역의 금리·실행금액을 현재 대출의 값으로 바꾸지 않는다. 금리, 차기 이자,
  미실행 중도금, 전체 원리금 상환 일정은 지원하지 않는다.
- 앱에서 파일을 선택하면 미리보기 요청을 보낸다. 서버 미리보기는 기록을 추가하지 않는다.
  본인 계좌와 값 확인 후 저장해야 새 관측값이 기록된다. 파일 내용·로그인 정보는 브라우저
  저장소에 보관하지 않는다. 파일 자체는 금융정보이므로 사용자가 보관·이동하는 동안에도 주의가 필요하다.
- 확인 파일의 조회 시각과 은행의 잔액 기준일은 다르다. `capturedAt`은 수집 시각이며
  `bankAsOfDate`는 확인되지 않아 항상 `null`이다. 날짜가 확인되지 않은 것을 오늘 기준 잔액으로 표시하지 않는다.

## 중복 합산과 기록

처음에는 합계에 넣지 않는 참고 기록이다. 사용자가 다음 중 하나를 명시적으로 선택한다.

1. 참고로 보관: 기존 합계에 영향 없음.
2. 별도 대출로 합산: 기존 수동 대출과 별개라는 확인을 거쳐 합산.
3. 기존 수동 대출과 연결: 같은 가족·소유자·공개 범위의 대출과 검토 당시 버전이 맞아야 한다.
   원래 수동 기록은 수정·삭제하지 않고 합계에서만 제외한다. 연결 대상이 변경되면 자동 대체하지 않고 다시 확인하도록 표시한다.

금액은 정수 문자열과 BigInt로 처리한다. 미확인값을 0으로 바꾸지 않는다. 동일한 대출의
공유 기록이 보이는 범위에서 중복되면 둘 중 하나를 임의로 고르지 않고 합산을 보류한다.
비공개 기록과의 중복 여부·금액·개수를 가족 합계나 응답으로 알려주지 않는다.

새 파일의 검토·저장 요청은 고정 request ID로 재시도한다. 동일 요청은 새 관측값을 중복 생성하지
않으며, 이전 요청으로 삭제·공유 철회·새 수정 내용을 되돌리지 않는다. 이전보다 오래된 수집값,
24시간을 지난 파일, 허용 오차를 넘는 미래 시각은 거절한다. 저장 확인 실패와 저장 실패를
같은 것으로 단정하지 않고 최신 기록 조회 또는 같은 요청 재확인으로 처리한다.

## 권한·민감정보

- 서버가 현재 로그인 사용자와 가족 구성원 권한을 확인한다. 계좌의 법적 소유권을 은행에
  확인하는 기능은 없으며, 본인 계좌 확인은 사용자의 확인이다.
- 기본은 가족에게 공유하지 않는 상태다. 가족 공유는 별도 선택과 확인이 필요하다.
  기존 비공개 자산을 가족에게 소급 공개하지 않는다.
- 본인 기록만 변경 가능하다. 조회 전용 구성원은 저장·수정·삭제할 수 없다.
- 공유는 현재 구성원 ID와 가입 시각에 연결한다. 탈퇴·제거 시 공유를 철회하고,
  재가입만으로 과거 공유가 복원되지 않게 한다. 가입 시각은 PostgreSQL 정밀도를 유지한다.
- 파일·DB에 전체 계좌번호, 비밀번호, 인증서, 쿠키, 세션 토큰, 원문 DOM을 저장하지 않는다.
  끝 네 자리와 계좌번호의 도메인 구분 SHA-256 비교 키를 사용한다. 이 키는 **가명 식별자**이며
  암호화나 익명화로 설명하지 않는다. 가족용 응답에는 비교 키를 포함하지 않는다.
- 오류에는 SQL 바인딩이나 은행 원문을 포함하지 않는다. 기존 실시간 갱신 알림에는 값이 아닌
  변경 신호만 발행한다. 은행 주문·송금·상환·약관 수락은 수행하지 않는다.

## DB·배포 전제

`0066_loan_import.sql`은 신규 테이블 두 개를 추가한다. `loan_records`는 현재 표시 이름,
공유 범위, 합산 방법과 버전이고, `loan_snapshots`는 검토한 원금·만기·수집 시각의 불변 기록이다.
삭제는 기록 숨김과 공유·연결 철회이며 기존 관측값을 물리 삭제하지 않는다. 보존 기간과
계정 영구 삭제 정책의 후속 검토가 필요하다. 이번 작업에서는 운영 마이그레이션을 실행하지 않는다.

운영 반영 전에 최종 타입·단위·실제 격리 PostgreSQL 연동·모바일 화면 검증을 통과해야 한다.
마이그레이션이 적용된 API를 먼저 준비하고 웹/모바일 번들을 맞춰 배포한다. 이전 앱으로
되돌릴 때 새 테이블을 역삭제하지 않는다. 구버전의 탈퇴·재가입 및 실시간 갱신 경로와 새 API의
공유 만료 판정을 함께 검증한 뒤 롤백 범위를 확정해야 한다. 이 문서는 배포 승인이나 배포 완료를 뜻하지 않는다.

## 검증 구분

이번 구현 이전에 사용자가 직접 로그인한 화면의 접근성 트리에서 대출 잔액·만기 등의 표시와
조회 이동을 확인했다. 이는 확장의 실제 DOM 선택자가 동작한다는 증거가 아니다. 확장 설치,
신한의 실제 DOM에서 수집, 실제 파일 저장, 앱으로의 실제 금융정보 전송·저장은 별도 미검증이다.
Aside의 확장 설치 지원 및 해당 은행의 허용 조건도 이 코드만으로 보장하지 않는다.

오프라인 합성 HTML, 계약·권한·동시성·중복 방지 테스트와 실제 은행 수집 성공은 구분해 보고한다.
테스트 실행 영수증 및 차단은 저장소 밖 `../shinhan-loan-validation/`에 남긴다.
운영·원본 checkout·파서 유지보수·별도 카드 정정·Toss 연동 파일은 이번 변경 대상이 아니다.
