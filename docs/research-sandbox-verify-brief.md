# 검증 지시서 — sandbox iframe에서 게임 엔진이 실제로 도는가 (2026-09-05)

> 선행 조사(`docs/research-game-library-2026-09.md`)가 Phaser 4.2.1을 추천하고
> Excalibur 0.32.0을 차선으로 뒀다. 다만 **실행 검증은 "확인 못 함"으로 남겼다.**
> 이 작업은 그 미확인 항목을 실제로 확인하는 것이다.

먼저 `docs/research-game-library-2026-09.md`를 읽고 시작한다.

## 왜 이것이 먼저인가

선행 조사가 지적한 가장 큰 위험은 엔진 성능이 아니라 **불투명 출처(opaque origin)에서의
자산 로딩**이다. 우리 미니앱은 `<iframe sandbox="allow-scripts">` 안에서 도는데,
`allow-same-origin`을 주지 않으므로 브라우저가 그 문서를 고유한 불투명 origin으로 다룬다.

같은 앱에 포함된 파일이라도 그 안에서는 동일 출처 자산이 아닐 수 있다. 이것이 막히면
**추천 자체가 무의미해진다** — 엔진이 이미지를 못 읽으면 게임을 만들 수 없다.

## 확인할 것

각 항목을 **실제로 실행해서** 확인한다. 문서를 읽고 추정하지 않는다.

1. **엔진 로딩**: `<script src>`로 Phaser UMD를 불러 `new Phaser.Game(...)`이 뜨는가.
2. **이미지 로딩**: 같은 디렉토리의 PNG를 `this.load.image()`로 읽는가. 실패하면 정확한
   콘솔 오류를 기록한다(CORS인가, 다른 이유인가).
3. **인라인 자산 우회**: 이미지가 막힌다면 data URI / 캔버스 생성 텍스처로 대체 가능한가.
4. **JSON 로딩**: 타일맵 JSON을 `this.load.json()`으로 읽는가.
5. **터치**: 포인터 이벤트가 iframe 안에서 정상 동작하는가.
6. **부모 통신**: `postMessage`로 부모에 상태를 보내고 응답을 받는 왕복이 되는가.
7. Excalibur로도 1·2·4를 반복해 차이가 있는지 본다.

## 검증 방법

이 저장소에 실제 파일을 만들어 확인한다.

- 검증용 파일은 `scripts/verify-sandbox-engine/` 아래에 둔다(임시 디렉토리이며 나중에 지운다).
- 호스트 쪽은 최소한의 HTML 하나로 충분하다 — iframe을 `sandbox="allow-scripts"`로 띄우고
  postMessage를 받아 콘솔에 찍는다.
- 로컬에서 정적 서버로 열어 확인한다(`file://`은 origin 규칙이 달라 결과가 다르다).
- **가능하면 실제 브라우저에서 연다.** 브라우저 자동화 도구를 쓸 수 있으면 쓰고,
  못 쓰면 그 사실을 적고 확인 가능한 범위까지만 한다.

## 지켜야 할 것

- 추정으로 통과를 적지 않는다. 실행하지 못했으면 "확인 못 함"이다.
- 앱의 기존 코드를 고치지 않는다. `scripts/verify-sandbox-engine/`와 문서만 만든다.
- 라이브러리를 프로젝트 의존성에 추가하지 않는다(CDN 또는 검증 폴더 안에서만).
