## 이번에 할 것

### 1. 20회 진입/이탈 수명 검증 — 유일하게 안 돌린 게이트

설계서 §11의 11일 행에 있다: **"20회 진입/이탈 뒤 게임 Game/Scene·등록 timer/listener 증가 0"**

- Phaser `Game`이 `destroy`로 실제로 사라지는지, `Scene`이 남지 않는지
- `session`의 재시도 timer, `input`의 pointer 리스너, `renderer`의 RAF가 누적되지 않는지
- 20회 반복 후 증가량이 **0**인지 수치로 남긴다

이 검증은 **자동화 가능하다.** 사람이 필요하지 않다.

### 2. `docs/rpg-s91011-report.md` 작성

앞 워커가 못 쓴 보고서다. **새로 검증하지 말고 `docs/evidence/rpg-s91011/`와 위 표를 근거로 쓴다.**
빠뜨리지 말 것:

- 도감 화면·오늘 변주·완료 구현 내용
- 격리 DB 결과 — 키별 raw와 `pg_column_size`가 **다르다는 것**
  (collection만 jsonb가 raw보다 작다: 2150 → 532)
- **동시 편집 손실 실측** — 해결했다고 쓰지 마라. `api-db.txt`의 `conflicts` 배열이 근거다
- OTA 크기와 목표 대비
- 위 1번 수명 검증 결과

### 3. `docs/rpg-s12-checklist.md` — 실기기 점검표

**슬라이스 12는 사람이 기기를 들고 해야 한다. 대신 하지 마라.**
에뮬레이터·Playwright 결과를 실기기 통과로 쓰지 마라.

설계서 §11의 12일 행을 사람이 따라 할 수 있는 점검표로 옮긴다. 항목마다
**무엇을 보고 통과/실패를 판정하는지** 구체적으로 적는다.

- iOS·Android 각각 기종·OS·WebView 버전 기록란
- 로컬 scheme 부팅 / 오프라인 셸 / 온라인 저장
- **실제 손가락** 패드 조작·행동 버튼 멀티터치
- 화면 회전 · safe-area · 글자 확대
- 백그라운드 복귀 · 강제 종료 후 재진입
- 망 단절 → 복구 시 저장
- 60Hz 기기 60초 산책에서 프레임 간격 p95 ≤20ms · 50ms 초과 <1%
- **첫 90초에 걷기 → 주민 → 획득 → 도감이 되는가**
- 두 사용자가 "누가 봐도 산책하는 장소인가"에 뭐라고 하는지 적는 칸
