# 웹 UI 규칙

- 창 모양은 용도마다 하나, 애플 HIG 구분을 따른다: 시트(거래 상세·선택지/안내), 입력 폼(폰 아래·넓은 화면 가운데), 액션 시트(내가 누른 동작의 확인 — 폰은 아래쪽에 떠 있는 카드), 얼럿(예상 못 한 문제만 가운데), 메뉴(값 고르기). 기준 표는 `components/ui/sheet-layout.ts`, `sheet-layout.test.ts`가 고정 — 사용자 지적, 전부 바텀 시트로 바꿨다가 '모든 걸 다 바텀 시트로 만들라고 한 건 아니었다', 이어서 '전문 애플 디자이너로서 생각해'(2026-11-05).
- 바텀 시트(거래 상세·BottomSheet 위젯) 높이는 내용만큼 최대 85%(`SHEET_MAX_HEIGHT`)로 두고, 끌어내려 닫는 손잡이(`SheetHandle`)를 단다 — 폰에서 상세가 화면을 거의 다 덮어 '바텀 시트가 아니다'라고 지적받음(2026-11-05).
- 상세 화면의 설정 값과 목록 필터는 라벨 붙은 드롭다운을 쌓지 않는다. 설정은 설정 앱 스타일 한 줄(이름 기본색·값 회색, 고르는 줄 ⌃⌄·창 여는 줄 ›), 필터는 칩 한 줄로 두고 둘 다 누른 자리 아래 드롭다운(`components/ui/picker-menu.tsx`)으로 고른다 — 사용자 지적, 입력 양식처럼 보여 디자인이 별로라고 함(2026-11-05).
- 누름 요소에는 hover 색과 함께 `active:` 눌림 표시를 둔다 — 폰에는 hover가 없고 웹뷰 탭 하이라이트를 껐다(2026-11-05 최종 검토). `design-scale.test.ts`가 고정한다.
- 같은 개념은 한 이름으로 쓴다(이름표는 `docs/ux-renewal-2026-11.md` §8 '이름 규칙'): 합계 제외·취소됨/환불·가족 공개/금액만 공개/나만 보기·공용 카드, 보조 버튼 '닫기'(버리기 확인의 남는 쪽만 '계속 입력하기'/'계속 수정하기'), 해요체, 내부 용어 금지 — 화면마다 '제외됨'·'요약만'·'뷰어'처럼 갈라져 있었다(2026-11-06 HIG 3단계).
- 금액 칸은 `AmountInput`, 여러 줄 칸은 `Textarea`, 화면 날짜는 `formatMonthDay`·`formatMonthDayTime`, 가계부 달은 `MonthNav`, 설정 줄은 `FieldRow`, 조건 칩은 `FilterChip`을 쓴다. 토큰 밖 글자 크기·모서리는 래칫 상한 0이라 새로 쓰면 테스트가 실패한다(2026-11-06 HIG 4단계).
- 값 고르기 메뉴를 잠글 때는 `PickerMenu`/`FieldRow`의 `disabled`로 Radix 트리거까지 잠근다. 버튼 disabled만으로는 Android 웹뷰에서 메뉴가 열려 저장 중에 고른 값이 무시됐다(2026-11-06 최종 검토).
- 드롭다운(값 고르기·⋯ 메뉴·가족 전환)은 터치에서 손을 뗄 때 연다 — `components/ui/dropdown-menu.tsx` 기본 동작. Radix DropdownMenu 는 원래 손가락이 닿는 순간 열려서, 스크롤하려고 줄에 손을 대면 메뉴가 열렸다(사용자 지적 2026-11-06). 손가락이 조금 움직이면 열지 않는다. Radix 를 화면에서 직접 쓰지 말고 이 부품을 쓴다.
- 가계부 조건 칩 줄(`transaction-filters.tsx`)은 `touch-pan-x`로 가로 팬을 받는다 — 칩이 전부 버튼·드롭다운이라 세로 페이지 스크롤이 가로 제스처를 가로챌 수 있다(SOO-46).
